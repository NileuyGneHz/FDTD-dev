# FDTD_WS — Metasurface FDTD Research Workspace

> A local workspace for metasurface researchers: **the researcher sets the direction, materials and
> geometry; the agent tunes parameters inside that locked design space with Lumerical FDTD until the
> target is met.** Paper reproduction is how we calibrate the model, not the end product.
> The same skill library is shared by **DSH** and **WorkBuddy**. **Windows only** (Lumerical ships on Windows).

## Product policy

1. **Researcher sets the direction** — target metrics (R/T/A, phase, efficiency, bandwidth) with tolerances.
2. **Researcher sets materials and geometry** — stack, materials, topology, period; may iterate or go inverse.
3. **Agent tunes** — only inside the locked search space, runs FDTD, stops when the target is hit or proven unreachable.
4. **Researcher judges** — whether the numbers are trustworthy and publishable; the agent only supplies evidence.

> Reproduce and Design are two separate modes: reproduction forbids tuning to match a paper,
> design allows optimization inside the locked space. See [`docs/product-context/README.md`](docs/product-context/README.md).

## Layout

```
FDTD_WS\
├─ AGENTS.md / CLAUDE.md     contract for AI assistants
├─ docs\                     process and decisions (L1–L5)
├─ cases\                    ten reproduced papers (read-only; paper and .fsp stay together)
├─ projects\                 active research (writable, same shape as cases)
├─ library\                  shared: materials / pure modules / schemas / figure styles
├─ skills\                   the only executable capability library
├─ agents\                   role packages (contract, params, orchestration, tools, evals, memory)
├─ tools\                    self-checks: structure, script ownership, size, host wiring
├─ defects\  journal\  iterations\
├─ _scratch\                 one-off scripts and intermediates (not committed)
└─ _archive\                 course media and historical logs (not committed)
```

## Archive unit — paper and project live together

```
P01_Absorber_Liu2010\
├─ README.md   §0 goal & acceptance · §1 paper · §2 parameters · §3 deviation diagnosis
├─ paper\      PDF + supplementary material (read-only)
├─ model\      .fsp (state) + .lsf (readable source) + spec_<id>.json (parameters)
├─ config\     sweep_*.json — parameters only, no logic
├─ results\    csv / figures / report.md / _p0.log
└─ notes\      traps, convention gaps, questions for the authors
```

No `.py` inside a unit: capability scripts belong to `skills/`, `.lsf` stays in `model/`,
one-off scripts go to `_scratch/`.

## Host wiring

| Host | Project entry | Note |
|---|---|---|
| DSH | `.agents/skills/<name>` | finds the project root via `.git` |
| WorkBuddy | `.workbuddy/skills/<name>` | uses the current directory only, no upward search |

Both are **real directories containing one junction per skill**, generated by script:

```powershell
python tools\skills-wire.py            # dry-run
python tools\skills-wire.py --apply
python tools\skills-doctor.py          # expect ALL GREEN
```

> Start every session at the `FDTD_WS` root. Opening `projects\R01_x` silently hides every project skill.

## Hard rules (full text in `docs/constitution/`)

1. **ASCII paths only** — the GPU engine fails with error 1113 and a mojibake dialog.
2. **Never edit a `.fsp` in parallel** — binary, no diff, no merge.
3. **No file above 100 MB** — GitHub rejects it outright.
4. **No `_p0.log`, no result** — `layoutmode == 0` + `_p0.log` + `Completed` in the log.
5. **Set a control experiment before drawing conclusions.**
