# defects/ — 缺陷追踪

## 职责

记录**已复现的坑**：不是"怀疑有问题"，是"确定会坏、有证据"。仿真域的一条缺陷通常是一类坑
（ASCII 路径、`getindex` 传波长、`run()` 静默失效……），不是单个 bug 单。

## 文件格式

```
D-<NNN>-<slug>.md
```

```md
# D-001 非 ASCII 路径导致 GPU 引擎 1113

## 根因
<机制，不是现象>

## 修复
<改了什么，或"无法修复，只能规避">

## 验证
<命令 + 期望输出；能重跑>

## 影响面
<cases/R0N 里哪些单元踩过>
```

## 约束

1. **三段齐全才算修完**：根因 / 修复 / 验证。缺一段就是"记了个现象"。
2. **验证必须是可重跑的命令**，不能写"已确认"。
3. **编号不复用**。修完不动文件，只把状态改成 `resolved`。
4. 单元 `notes/` 里的坑，收敛后开一条 D 号；**不要在两处各写一份**（`notes` 留上下文，`defects` 留结论）。
5. **状态行必填且取值封闭**（2026-11-11 新增）。每条 D 的一级标题下必须紧跟一行：

   ```
   **状态**：`resolved`  或  **状态**：`unresolved`
   ```

   | 值 | 含义 |
   |---|---|
   | `resolved` | 已修，且「修复 / 验证」两段齐全、验证命令可重跑 |
   | `unresolved` | 未修 / 部分关闭 / 待裁决——**必须在括号里写清卡在哪** |

   **不要**自造词（`已修` / `待裁决` / `部分关闭` 都是 2026-11-11 之前的历史写法，已统一）。
   判据：`tools/check_docs.py` 机检，正则 ``\*\*状态\*\*：`(resolved|unresolved)` ``。
   统计：17 条里 14 `resolved` / 3 `unresolved`（D-009 部分关闭、D-014 待裁决、D-016 不可恢复）。
