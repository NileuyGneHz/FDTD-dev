# 归档单元契约

> 一个单元 = 一篇论文 / 一个课题。论文、工程、参数、结果，**四者必须互相对得上**。

## 必备结构

```
<unit>/
├─ README.md     §0 目标与验收 · §1 论文 · §2 参数 · §3 偏差诊断
├─ paper/        论文 PDF + 补充材料（只读）
├─ model/        .fsp + .lsf + spec_<id>.json
├─ config/       sweep_*.json / run_*.json（只有参数）
├─ results/      csv / 图 / report.md / _p0.log
└─ notes/        踩坑、口径差异、待问作者
```

## 逐项规则

| 目录 | 必须 | 规则 |
|---|---|---|
| `README.md` | ✅ | 四段齐全；接手者只看它就能开工 |
| `paper/` | ✅ | 不改名、不移动、不改内容；命名 `<AuthorYear>_<Journal>.pdf` |
| `model/` | ✅ | **路径纯 ASCII**；`.fsp` 是状态、`.lsf` 是源、spec 是参数，三者同放，不许二选一 |
| `config/` | ○ | 只有参数，没有逻辑；脚本从它读输入 |
| `results/` | ○ | 一次运行一个子目录；必须有 `_p0.log` 才能声称"算过" |
| `notes/` | ○ | 写"还没定论的东西"；每条最终收敛成 `defects/D-xxx` |

## 四条禁止

1. **不跨单元引用论文**。要引用就把文件放进本单元。
2. **不在单元内放 `.py`**。脚本归技能（见 `script-contract.md`）。
3. **不把 `.fsp` 与论文分家**。工程离开论文 = 半年后没人知道它对应哪版参数。
4. **不删 `_p0.log`**。它是"到底算没算"的三判据之一。

## README 四段模板

```md
## §0 目标与验收
要复现哪张图、判据是什么（峰值 A / 峰值波长 / FWHM）、容差多少。

## §1 论文
文件、DOI、原文声称的结论原文引用。

## §2 参数
从 spec 里摘关键量（a / l / w / t / 材料模型），与论文出处逐条对应。

## §3 偏差诊断
差多少、怀疑哪一层（参数 / 模型 / 收敛 / 物理）、下一步验证什么。
```
