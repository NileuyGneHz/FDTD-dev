# docs/plans/ — L4 方案

## 职责

存放**有日期的实施/重构方案**：打算怎么改、分几步、每步怎么回退。不是需求，也不是任务。

## 格式

```
PLAN-<YYYYMMDD>-<slug>.md
```

## 内容要求

1. **现状**：为什么现在改（一句话 + 证据）
2. **目标态**：改完长什么样
3. **步骤**：每步可独立回退，标注影响面
4. **风险**：最坏情况与止损点
5. **验收**：怎么知道改成功了

## 约束

1. **没有回退方案的 plan 不许执行**（本工作区无版本控制时尤其如此）。
2. 方案被替代就**删掉**，历史在 git 里；不要留两份互相矛盾的 plan。
3. 执行完的 plan 移到 `archive/` 或在顶部标 `DONE` + 日期。
