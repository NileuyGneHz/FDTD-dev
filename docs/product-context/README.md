# Product Context — FDTD 超表面研究工作空间

> 本文件是 L1，全仓库最稳定的一层。它一变，所有 Spec / Plan / Task 都要复审。
> 每次会话开始读一次，五分钟入项。

## ① 一句话定位

面向超表面科研人员的本地 Lumerical 工作空间：**把论文变成可复现、可对照的模型**，
并让 DSH 与 WorkBuddy 两个 AI 宿主按同一套技能接管「读论文 → 建模 → 跑谱 → 判偏差 → 出图」。

## ② 用户与问题

- **用户**：做超表面 / 超材料数值研究的研究生、博后、科研工程师。
- **问题**：
  - 一篇论文的参数散在正文、图注、补充材料里，靠人肉翻；
  - `.fsp` 工程与论文分家，半年后说不清这个工程对应哪一版参数；
  - 仿真结果对不上文献时，无法区分"模型错"还是"参数读错"；
  - 同一个人第二次做同类结构，还得从头再踩一遍坑。

## ③ 北极星指标

- **一篇新论文到第一张可信 R/T/A 谱**：≤ 1 个工作日
- **复现失败时能立刻回答"错在哪一层"**（参数 / 模型 / 收敛 / 物理）的比例：100%
- **任一单元只读 `README.md` 就能接手**：100%

## ④ MVP 范围（In Scope）

- 论文参数萃取 → 结构化 **spec JSON**（长度用米、材料带 cite、缺项进 `missing`）
- 单元胞建模与扫参（box / polygon / cylinder / ellipse / sphere / ring；drude / constant_nk /
  constant_eps / builtin / sampled_nk）
- R/T/A 谱与相位提取；收敛判据以 `_p0.log` 的 `Auto Shutoff` 为准
- 每个课题一个**归档单元**：论文 PDF + `.fsp` + `.lsf` + spec + 结果，同包不分离
- 双宿主接入：DSH 与 WorkBuddy 读同一批技能（`skills/`），入口由脚本生成

## ⑤ 非目标（Out of Scope）

- 不做文献综述平台、不做论文排版、不做云端渲染
- 不做多用户在线协作（本仓库是单机 git 工作区）
- 不自动"调参凑图"——**任何为了贴合文献而改参数的行为都算数据造假**
- 不做全器件仿真（透镜、全息）：本工作区只做单元胞与周期阵列

## ⑥ 成功的样子

半年后回看任意一个单元：论文、参数、工程、结果、当时的判断，五样东西在同一个目录里，
且能说清"为什么这个数当时代替了那个数"。

## ⑦ 与 AI 的分工

**AI 负责**：找参数、写脚本、跑仿真、比曲线、把证据摆出来。
**人负责**：判断数值是否可信、结论是否成立、图是否可发表。
**红线**：AI 不得替人下"复现成功"的结论，只能给证据。
